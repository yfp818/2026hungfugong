# 部署模組

## 用途

本文件用來記錄正式環境的部署規則與部署指令。

閱讀本文件，不代表要立即部署。

## 正式環境資料

- Google Cloud 專案：`my-project2026dijun`
- Cloud Run 服務：`hungfugong-web`
- 部署區域：`asia-east1`
- 正式網站：`https://huangfugong2026.com`

## 最重要規則

不得自動部署。

只有使用者明確說出以下類似指令時，才可以部署：

- 部署正式環境
- 幫我部署
- 執行 Cloud Run 部署
- 將目前版本上線
- 把這次修改部署到正式網站

以下要求不代表允許部署：

- 修正程式
- 修改頁面
- 檢查問題
- 執行 Build
- 測試功能
- 提供部署指令
- 更新文件
- 完成功能

## 正確工作流程

1. 先分析問題。
2. 只修改必要檔案。
3. 執行：

```bash
npm run build
```

4. 回報 Build 結果。
5. 停止操作，等待使用者確認。
6. 使用者明確要求部署後，才可以執行正式部署。

Build 成功不代表已經部署。

## 正式部署指令

以下指令只是提供 Codex 參考。

編輯本文件時不得執行。

Build 成功後，也不得自行執行。

只有使用者明確要求部署時，才可在專案終端機執行：

```bash
gcloud run deploy hungfugong-web \
  --source . \
  --project my-project2026dijun \
  --region asia-east1
```

## 環境變數規則

- 必須保留 Cloud Run 目前所有環境變數。
- 不得自行加入 `--set-env-vars`。
- 不得自行加入 `--env-vars-file`。
- 不得刪除或覆蓋既有環境變數。
- 不得顯示 Secret 或密碼內容。
- 只有修改環境變數時，不一定需要重新部署程式。
- `ADMIN_LINE_USER_IDS` 用來設定管理員的 LINE User ID。

任何環境變數修改，都必須另外取得使用者明確同意。

## 部署前確認

部署前必須確認：

- 使用者已明確要求部署。
- `npm run build` 已成功。
- 修改內容符合使用者要求。
- Google Cloud 專案是 `my-project2026dijun`。
- Cloud Run 服務是 `hungfugong-web`。
- 部署區域是 `asia-east1`。
- 不會刪除或覆蓋既有環境變數。

任何一項無法確認，就停止部署。

## 部署後回報

部署完成後必須回報：

- Build 是否成功
- 部署是否成功
- 新的 Cloud Run Revision
- Cloud Run 服務網址
- 正式網站測試結果
- 所有警告或錯誤

沒有實際部署指令的成功結果，不得說已經部署完成。

## 正式環境測試

只測試本次修改影響的功能。

例如：

- 修改登入：測試登入與登出。
- 修改會員：測試會員資料讀取與儲存。
- 修改管理員：測試管理員權限。
- 修改資料庫：測試相關資料讀取或寫入。
- 修改畫面：測試相關頁面。

不得在正式環境進行破壞性測試。

## 禁止事項

- 不得自動部署。
- 不得因為 Build 成功就直接部署。
- 不得更換 Google Cloud 專案。
- 不得更換 Cloud Run 服務名稱。
- 不得更換部署區域。
- 不得覆蓋環境變數。
- 不得顯示 Secret。
- 不得在未找出問題前反覆部署。
- 未實際部署成功，不得說正式網站已更新。
